Honest reading: Merchant-only beats Full Graph on the POINT ESTIMATE in all 4/4 windows, and is
statistically distinguishable in 2/4 (Window 0 with 5 seeds, Window 1 with 3 seeds). In Windows 2
and 3 the higher per-seed variance (std up to 0.0355) combined with only 3 seeds widens the CI
enough that the two conditions' intervals touch. This does NOT mean the effect is unreal -- the
direction is consistent 4/4 times, which is itself informative under a sign-test-style read
(p=0.0625 for 4/4 same-direction under a fair-coin null, one-sided) -- but it does mean the
per-window magnitude claims in Windows 2-3 should be stated as "consistent with, not proven by,"
this experiment's seed count.

------------------------------------------------------------------------------------------------
Limitations of this statistical treatment (read before citing p-values/CIs externally)
------------------------------------------------------------------------------------------------
1. Small n (3-5 seeds): t-based CIs with df=2-4 are wide and sensitive to individual runs; a
   single unusual seed can shift the interval substantially (e.g. Window 1 seed 1 Merchant-only
   =0.2002 vs seeds 0/2 ~0.244, pulling that window's std up).
2. Small positive-class counts: Window 0's test split has only 354 fraud transactions (out of
   271172); Window 3's has fewer still relative to its smaller test set. PR-AUC and
   Precision@200 are themselves high-variance estimators with this few positives -- a handful of
   transactions changing rank order can move PR-AUC by hundredths. The seed-to-seed std already
   captures some of this, but a more rigorous treatment (not done here, flagged as future work)
   would bootstrap-resample the test-set predictions directly rather than relying solely on
   training-seed variance.
3. Std values recorded in the results files are population std (numpy default, ddof=0) not
   sample std (ddof=1); at n=3-5 this understates the interval slightly. The CIs above are
   therefore mildly optimistic (narrower) versions of a stricter ddof=1 computation.
4. No multiple-comparisons correction was applied across the many pairwise comparisons run
   throughout this project. Individual comparisons above should be read as descriptive, not as
   a pre-registered hypothesis test surviving correction for the number of comparisons made.
