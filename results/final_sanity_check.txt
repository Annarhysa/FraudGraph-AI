2. Rebuild dataset from raw CSV and verify counts against the final audit
------------------------------------------------------------------------------------------------
Ran `python -m src.fraudgraph.data_prep` against a moved-aside (backed up, not deleted)
data/processed/ directory.

  FINDING (reproducibility gap, non-blocking): data_prep.py's filler-user sampling
  (`USING SAMPLE {N} ROWS` in DuckDB, src/fraudgraph/data_prep.py build_sample()) has NO fixed
  seed. Fraud-user rows are always included deterministically (fraud count matched exactly:
  2087 fraud txns, 0.312% base rate, identical to the audit both times) but the 300 randomly
  sampled non-fraud "filler" users differ run to run:
    Audited (results/final_results_tables.txt, methodology.txt): 677,930 txns, 466 users,
      1,502 card-pairs, 14,868 merchants.
    This rebuild:                                                 669,785 txns, 456 users,
      1,443 card-pairs, 14,753 merchants.
  Practical impact: none of the reported PR-AUC/statistical conclusions depend on which specific
  non-fraud users are sampled (fraud rows, the only rows that matter for PR-AUC's positive class,
  are always the same). But this means a literal "pull and rebuild reproduces the exact published
  counts" claim did NOT hold at the time of this check.
  The canonical processed artifacts (matching the published 677,930/466/2087 figures) were
  restored after this check — see step 14.

  UPDATE (same day, follow-up fix): switched build_sample() to
  `USING SAMPLE reservoir(300 ROWS) REPEATABLE (42)` plus `SET threads = 1` on the DuckDB
  connection (REPEATABLE alone was not sufficient — DuckDB's parallel scan order still varied
  the sample; single-threaded execution was required to pin it). Verified deterministic across 3
  consecutive clean reruns (649,480 txns / 454 users / 2,087 fraud, identical every time). This
  seed was necessarily added AFTER the dataset behind every published result already existed
  (from an unseeded run), so it cannot retroactively reproduce the historical 677,930/466 draw —
  it guarantees a FUTURE clean rebuild reproduces itself exactly, not that it matches the
  already-published numbers. The production data/processed/ artifacts were left as the original
  677,930-txn dataset (not regenerated against the new seeded sample), so nothing published
  changed. Full detail: results/reproducibility_audit.txt.
